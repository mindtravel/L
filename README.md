# L

> 每一步画一个 L，围成格子，连成四格。

## 启动

项目使用原生 ES Modules，必须通过 HTTP 服务打开，不能直接用 `file://` 双击页面。

```bash
npm install
npm start
```

然后打开 <http://localhost:8000>。联机时创建房间，把网页地址和房间号发给对手即可。

服务端同时提供静态页面和 WebSocket 房间。房间局面只保存在服务端内存中，进程重启后房间会消失。

## 发布

Render 已连接 GitHub `main` 分支，因此推送成功后会自动部署。使用下面的命令完成检查、提交和推送：

```bash
npm run release -- --message "说明这次改动"
```

脚本会运行测试、生产依赖审计和差异检查，然后提交所有未暂存变更并推送 `origin/main`。只预览不修改：

```bash
npm run release -- --message "预览" --dry-run
```

只提交不推送可加 `--no-push`；跳过审计可加 `--no-audit`。脚本会拒绝疑似密钥文件，也会在发现已有暂存内容时停止。

## 规则

规则遵循“没有写禁止的事情，就允许”。

### 下棋

双方轮流在格点上画一个 `L`：两条互相垂直、各一格长的线段，四个方向任选。

### 种子

接上己方已有线段，不消耗种子；没有接上己方线段，消耗一枚种子。没有种子时不能这样落子。

### 不重叠

新线段不能覆盖已有线段。接触、共享格点、交叉和跨越边缘都允许。

### 胜负

四条边被同一方占满的格子归该方。己方格子横、竖或斜向连成四格，获胜；没有合法落子时和棋。

### 棋盘

棋盘左右相连、上下相连。棋盘尺寸可选 13、15、17、19、21 格，默认 13 × 13。

棋盘外的淡色部分是从对边接过来的预览，那里也可以落子。棋盘下方的两根轴只改变观察接缝，不改变局面。

## 操作

点一个格点，再点四周的一个 L。实线表示续线，点线表示消耗种子的落子。

快捷键：`1`–`4` 落子，`Esc` 取消，`U` 悔棋，`R` 新局，`H` 开关提示。

开始页先选模式：双人同机、人机或联机。只有联机模式显示创建/加入房间；AI 模式显示 AI 强度。

## 工程结构

```text
js/
├── rules.mjs                    纯规则内核，浏览器与服务端共用
├── ai.mjs                       简单攻守策略
├── board-view.mjs               Canvas 绘制、几何和选择状态
├── application/
│   ├── game-engine.mjs          局面流程和历史
│   ├── game-controller.mjs      本地、AI、联机共用的命令入口
│   ├── setup-controller.mjs     开始页模式和房间设置
│   ├── online-session.mjs       联机连接状态和命令
│   └── game-snapshot.mjs        规则状态与网络 DTO 的版本化边界
├── infrastructure/              WebSocket 和协议校验
├── presentation/                HUD DOM 投影
└── main.mjs                     唯一组合入口
server.mjs                       静态资源与权威联机服务
```

规则模块不读取 DOM、Canvas 或 WebSocket。联机会话不解释规则，只传输命令和版本化快照；服务端再次用规则内核校验落子。

快照包含 `rulesVersion`。以后改规则时，先改纯规则测试，再更新快照契约和协议测试，最后验证 WebSocket 与 UI。

## 测试

```bash
npm test
npm audit --omit=dev
```

测试覆盖规则、AI 攻守、会话权限、快照隔离、协议输入、Canvas/UI smoke，以及真实 WebSocket 建房、广播、去重、重连和再赛。
